# Built

How each finished part works, newest first, kept as reference for changing it later. Everything here is verified (see `docs/STATUS.md`); nothing here is open work.

- **Phase 6, edit mode, lifecycle and the styling pass (2026-10-28).** **Title bar:** a plain 28px row in the window's flow (`.window-header`, Foundry's window gap set to 0); only ⋮, × and dnd5e's warnings show, every other `.header-control` is hidden by CSS and listed in dnd5e's ⋮ menu by our `_getHeaderControlContextEntries` (`compat.extraHeaderControls`; the entry clicks the real button). **Header** (`templates/sheet/header.hbs`, `src/sheet/header.js`): the portrait card is a 160 × 234 frame (`framedPortrait`: a token shows whole, other art covers at its framing; round drops the card's edge); framing (`src/apps/framing.js`) saves `flags.fhcs.portrait` keyed by the image, `flags.fhcs.portraitShape` the shape. Inspiration alone on the art; the portrait's options (token switch, round, Frame) in one gear chip's tray. The name row ends in the status group (exhaustion with its tray, `rest` per type, hit dice; `data-fhcs-tip-cut` shows a cut name on rest). The HP band: the bar opens the HP tray in play (`fhcsHpChange` → `compat.changeHp`: dnd5e's `applyDamage` / `applyTempHP`; edit mode keeps dnd5e's meter), Temp and Max ± (`tempmax`) as bars. The stats row: the combat panel (shield, Init `roll`, Prof, the Level button holding the level tray: Level up, New class, edit mode's Level down via `compat.levelDownClass`) and the abilities panel (score | `ability-check` modifier, `saving-throw` with a shield filled when proficient); in edit mode scores, name and XP are fields and gears open dnd5e's `showConfiguration` windows. Cards sit on the stats row's columns (`classSpans`: one class takes the combat column and two abilities'). **Attributes:** skills are dnd5e's row model (one `li`, fixed 24px cells; edit mode lays dnd5e's `proficiency-cycle` unseen over our mark, and the ability opens a chip tray, `fhcsSkillAbility`); traits sit at the main column's top, foldable with the favorites groups (`foldedFavorites`), every trait in both modes; Resources lists dnd5e's three legacy resources from the actor, first among the favorites; a favorited effect shows its switch (`useFavorite`). **Effects:** a concentration gets Break (`fhcsEndConcentration`) in Delete's place; concentration's mark is drawn (`conc-c.hbs`). **Styling rules** (SCOPE §5.2, 1–21) are enforced by the layout check: a real Foundry title bar and window gap imitated; every element both modes draw keeps height, place and text position; like chips match; one text size per control; no capitals in buttons; gears no larger than their words; spacing 0, 4 or 8 bar the named hangs and column indents; no glow on tabs. Offline: unit, load, 426 layouts; Quench core in the user's world; play by the user.

- **Phase 5, Features, Effects, Biography and the header cards (2026-10-27).** All three tabs take dnd5e's part IDs. **Features** (`templates/sheet/features.hbs`, rows `feature-row.hbs`) sits on `dnd5e-inventory` like Inventory; `compat.featuresFacts` reads dnd5e's `context.sections` (each with one `groups` entry: `origin` or `activation`) and each row's `ctx.groups`. Every section of both groupings is drawn with `data-group-<key>`, and every row carries both its groups, so dnd5e's own `_applyGrouping` moves rows when the grouping changes; our "By source" button (`fhcsCycleGroup`, `compat.cycleListGrouping`) steps dnd5e's hidden group button, which saves the choice in its user flag (`sheetPrefs.character.tabs.features.group`). Recovery is in words from `limitedUsePeriods` labels; a spent recharge is dnd5e's `recharge` action. Columns are the client setting `featureColumns`. **Effects** (`effects.hbs`) sits on `dnd5e-effects`, which binds every `[data-action]` inside it (`toggle`, `toggleExpand`, `favorite`/`unfavorite`, `edit`, `delete`, `toggleCondition`, right-click lowering exhaustion) and the context menu on `[data-effect-id]`. `compat.effectsFacts` files dnd5e's Temporary, Passive and Inactive effects by `effect.isTemporary` into Temporary or Passive (so a switch never moves a row) and sorts by `sort` then name; Suppressed stays apart. A concentration effect shows the C mark, not the switch. **Biography** (`biography.hbs`, boxes `bio-box.hbs`) uses dnd5e's own field names (`system.details.*`), so text carries over between sheets; whoever may edit (`sheet.isEditable`) gets inputs in play mode too, which dnd5e's form saves on change (its `_disableFields` only stops viewers); the biography is `<prose-mirror toggled>`. **Header cards** (`src/sheet/origins.js`, `compat.originFacts`): the class, species and background cards are a second row of the ability grid (`grid-template-columns: repeat(var(--fhcs-columns), …)`), spans from `classSpans`; `needsSubclass` is dnd5e's own test (Subclass advancement level reached, none owned); Choose is dnd5e's `findItem`, remove its `deleteDocument` (which asks and offers to undo advancements); species and background are dnd5e singletons, so change is remove then choose. The art is an underlay at 25% under a mask, so text keeps 4.5:1. **Level up** (`level-up.hbs` in the level pill's tray, XP and milestone mode): `compat.levelUpClass` repeats dnd5e's private `#changeLevel` (`AdvancementManager.forLevelChange(actor, id, 1)` rendered with `_renderChild`, or a plain level change when advancements are off); New class is `findItem` with type class. Every list alternates a faint fill (`:nth-child(even of :not([hidden]))`, kept light with `:where` so tints win). Lessons: a dnd5e list that files by state (Inactive) moves rows on a click; the layout check now fails when a short fixed word is cut short.

- **Phase 4, Spellbook tab (2026-10-26).** `templates/sheet/spellbook.hbs` takes dnd5e's `spells` part, built on `dnd5e-inventory` like Inventory; rows are `templates/sheet/spell-row.hbs` (dnd5e's `use`, `toggleExpand`, `prepare`, `toggleFavorite`, `edit`, `delete`), the search bar the shared `list-bar.hbs`. `compat.spellbookFacts` reads dnd5e's `context.spellbook` sections (`_prepareSpellbook`, one per slot key plus `pact`, `innate`, `atwill`, `ritual`, `item`), its row context (`_prepareItemSpell`), `context.spellcasting` for the class cards and the actor's concentration effects; `src/sheet/spellbook.js` `spellbookView` builds the display values. Sections sort by `sectionRank` (method, then level); the book's three states come from `prepState`, the row's kind (tint and word) from `spellKind`, used on Attributes favorites too. Slot pips are drawn in our headings with dnd5e's `togglePip`; `_renderSpellbook` is overridden empty (dnd5e's would add its own pips). Concentration bar: open (`fhcsOpenConcentration`), End (`fhcsEndConcentration`, `compat.endConcentration`), Con save (`roll`). Extra filters Can cast and V, S, M (`EXTRA_SPELL_FILTERS`) run in our `_filterItem` after dnd5e's (`compat.passesExtraFilters`; `canCast`: uses left when it has uses; else cantrips, item-linked, at-will, innate and ritual-only spells; else prepared and either a ritual or a slot left at or above its level). Columns are a client setting (`spellColumns`, school and target off by default); the favorite toggle column is on Inventory rows too. Attributes favorites open their details in place (`fhcsToggleFavoriteDetails`) and use the item from the picture. Verified in Quench (core 35 of 35) and in play, including a multiclass Pact Magic caster.

- **Phase 3, Inventory tab (2026-10-26).** `templates/sheet/inventory.hbs` takes dnd5e's `inventory` part, built on `dnd5e-inventory` so dnd5e binds the rows (`.item-action[data-action]`: use, equip, attune, toggleExpand, edit, delete), numeric fields by `data-name`, the context menu and drag on `[data-item-id] > .item-row`. dnd5e renders every item into one hidden list and sorts rows into sections in the browser; `compat.inventoryFacts` places them by item type instead, and puts containers back as rows (dnd5e lists them apart). A container's contents are drawn under it at any depth (`rowFacts` recurses; `containedContext` runs dnd5e's per-item steps, which skip contained items); rows inside carry no `data-parent-id`, so dnd5e's filter matches them. Search shows a match inside a shut container (`showMatchesInContainers`, a `MutationObserver` on dnd5e's `hidden` passes). The row partial is `templates/sheet/item-row.hbs`; the search bar is the shared `list-bar.hbs` (dnd5e's `item-list-controls`, pinned filters, Columns menu). Columns are a client setting (`inventoryColumns`, `fhcsToggleColumn`); open containers a user flag (`openContainers`). `_renderAttunement` is overridden: our footer draws attunement, currency and carried weight (hidden when dnd5e's encumbrance setting is off). Our trays close on a pointerdown anywhere else. dnd5e marks the sort button active always; our CSS lights only filter and search. Lessons: dnd5e keeps attunement only on magical items (`mgc`); each create starts its own redraw.

- **Phase 2b, Attributes tab (2026-10-24).** `templates/sheet/attributes.hbs` takes dnd5e's `details` part (same ID and container). `compat.attributesFacts` reads skills from `actor.system.skills`, traits from dnd5e's `_prepareTraits`, `_prepareSenses` and `_prepareSkillsTools`, and favorites from `_prepareFavorites`, grouped by us (Inventory, Features, Cantrips, Spell level N, Effects, Skills and tools, Other); `src/sheet/attributes.js` builds the view. Skills roll through dnd5e's `roll` (`data-type="skill"` under `[data-key]`); favorites use dnd5e's `useFavorite`; slot pips use `togglePip` on `system.spells.spellN.value`. Passive toggle (`fhcsTogglePassives`) and folded groups (`fhcsToggleGroup`) are user flags, so each player's choice follows them. Equipped: green tint, left edge, tick; prepared: blue, bookmark. Edit-mode config buttons for traits wait for Phase 6. Offline: unit (passives, marks, traits, group order, pips; seen failing), layout (4 cases). Quench: one more core test.

- **Phase 2a, our own frame (2026-10-24).** Our window drops dnd5e's look classes (`dnd5e2`, `vertical-tabs`, `hidden-title`) in `_initializeApplicationOptions`, so none of dnd5e's sheet styles apply; dnd5e's code doesn't look for them. dnd5e's sidebar part is gone (portrait, HP, AC in our header; favorites move to Attributes; death saves to the header). `templates/sheet/tabs.hbs` replaces dnd5e's vertical tabs: Classic's order and names (Attributes, Inventory, Spellbook, Features, Effects, Biography, Bastion), Special Traits only in edit mode, the lock (dnd5e's `changeMode`) at the right; dnd5e's own mode switch in the window header is hidden. Header and tab row stay put; tab bodies scroll. dnd5e's tab bodies render with Foundry's plain styles until each phase replaces them. Offline: load (parts, classes; seen failing), unit (tab row), layout (tab row at 644 with eight tabs). Quench: two more core tests.

- **Phase 1 header (2026-10-24).** `templates/sheet/header.hbs` replaces dnd5e's `header` part and drops `abilityScores` (`src/apps/CharacterSheet.js`); dnd5e's sidebar, tabs and tab bodies stay for now, so the portrait, HP and AC also still show in dnd5e's sidebar until Phase 2. `compat.headerFacts` gathers dnd5e's data, `src/sheet/header.js` `headerView` builds the display values. - **Track R slice 1, card frame.** `src/chat/card.js` subclasses dnd5e's usage-message model (`compat.extendChatModel`) and swaps in `templates/chat/usage-card.hbs`: portrait, title, folded description (with flavor, materials and tags), dnd5e's roll buttons as full-width bands (`data-action` + `data-index`), other actions as centered buttons; targets, summaries and effect tray as dnd5e has them. - **Track R slice 8, standalone rolls.** `src/chat/roll-card.js` subclasses dnd5e's check and save models (drawn as `templates/chat/roll-card.hbs` when not folded into a usage card or a request) and its request model (`request-card.hbs`: one row per target; `handleRequest` reads `data-uuid`, a result's row carries its message id). Request results (`flags.dnd5e.requestResult`, `compat.requestOf`) hide and refresh the request on late adds. Header, rolled band, d20 row and bonus field are shared parts (`templates/chat/parts/`), preloaded at init; the load check fails if a part is included but not preloaded.

- **Track R slice 7, late adds.** `compat.addD20` adds a die on a side, rolled then (`freshD20`, with Dice So Nice; no die is rolled in advance since 2026-10-28, and an old roll's `fhcs.spare` is dropped on its next change), keeps every die, marks the counting one (`d20.js` `countingDie`, `modeForSides`) and saves the roll in place (`message.update({ rolls })`); `compat.addBonus` rolls a formula and appends its terms. `rollFacts` records `canEdit` (author or GM) and bonuses. `rolls.js` `refreshOnRollChange` (`updateChatMessage`, every client) re-renders the card via `compat.refreshCard`, since dnd5e refreshes only on `system` changes. Known gaps: Reliable Talent and Halfling Lucky don't apply to dice added late.

- **Track R slice 6, roll on use, no dialogs.** `src/chat/rolls.js`: `rollOnUse` (`dnd5e.preUseActivity`) switches off dnd5e's own follow-up rolls when our settings are off; `damageAfterAttack` (`dnd5e.postRollAttack`) and `damageAfterUse` (`dnd5e.postUseActivity`, save activities) roll the card's damage via `compat.rollCardDamage` (explicit `system.origin`, no dialog, critical from the attack); `skipRollDialog` (`dnd5e.preRoll`) sets `dialog.configure` unless `compat.skipKeyHeld`. World settings `rollAttackOnUse`, `rollDamageOnUse`, `noRollDialogs`. Known gap: auto damage posts in the default roll mode, not the attack's.

- **Track R slice 5, apply.** The card's Apply section wraps dnd5e's `damage-application` in an element carrying the latest damage message's id (the tray reads its damage and each token's save outcome from the nearest `data-message-id`), plus dnd5e's `effect-application`; `compat.openTrays` unfolds both after dnd5e's own collapse setting runs; `compat.canApplyDamage` follows dnd5e's player-tray setting. Secondary actions (template, consume) moved below Apply.

- **Track R slice 4, save band.** Save and check messages fold into the card; `card.js` `saveRow` draws one row per message answering the band's button (`compat.answersButton`: skill, tool or ability). Each row carries its save's `data-message-id`, so dnd5e's `resistSave` works inside it. `compat.preferSelected` sets the card's targeting mode to selected (dnd5e's default is targeted). dnd5e's own summary rows for saves and checks are dropped. Unit: 3 save rows; layout: Fireball with three saves.

- **Track R slice 3, damage band.** Damage and healing messages fold into the card (`FOLDED_TYPES`); `compat.damageFacts` and `card.js` `damageBand` draw the total, totals by type, critical and on-save words, each roll's math; `compat.rollDamageAgain` re-rolls as a critical or not without the dialog (our `data-fhcs-action` buttons, author or GM only). Unit: 4 damage cases; layout: 2 damage cases.

- **Track R slice 2, d20 band.** `src/chat/rolls.js` hides attack cards whose `system.origin` is a usage card (`dnd5e.renderChatMessage`); it no longer adds a spare d20 to each roll (removed 2026-10-28 with the `fhcs.twoD20s` setting; the load check fails if anything hooks `dnd5e.postRollConfiguration`). `src/chat/card.js` `d20Band` and `src/chat/d20.js` `d20Row` draw the latest attack: total, d20 row (primary center, disadvantage left, advantage right; `roll.options.fhcs.sides` reserved for late adds), outcome words, dice math, earlier totals, Roll again. Offline: unit 6 d20-row cases; layout 3 rolled cases.
